# B-1229 歩行可能帯の推定改善（2026-11-28、Gemini 4 生成＋リード手直し2件）

経路: AI Studio（Gemini 4 Hydrogen）へ指示書（41,314 バイト）を渡し (A)(B)(C) を生成。チャット: https://aistudio.google.com/prompts/1mOdBSbiFep8oBNbNRZ1R9RoT6BKpv3eH 。生成は設計どおりで、SPEC_KEYS 検査との矛盾（spec に waypoints を入れない判断）も生成側が正しく指摘した。

## 成果物（ai_loop/image_scene.py）
- `route_waypoints(spawn, waypoints, footprints, walk)`（新規）: walk 領域をグリッド化し、footprints（collision_candidates の [cx, cz, width]）を膨らませて塞ぎ、各脚を決定的 A* で結ぶ。直線が通る脚は不変、角だけを中間ウェイポイントとして挿入、経路が無い脚は元の目標を残し routed: false で正直に記録。
- analyze は report の waypoints を経路済みに差し替え、`"walk_routing"`（脚ごとの from／to／routed／inserted）を追加。
- テスト追加3件（障害物なしは不変／中央の壁は側方を迂回し全脚到達可能＋決定的／全面封鎖は routed: false）。

## リードの手直し: 2件（どちらも実測に基づく設計補正）
1. **塞がれた端点の扱い**: 初版は目標点自体が膨張フットプリント内にあると経路なしになった。実測では moonpost の目標 (0,-11.65) が中景カードの膨張範囲内に入るが、実コライダは厚さ 0.2 m（build_tool.gd の cbox）の薄いカードで、歩行者は到達圏内まで近づける。端点が塞がれている場合は最寄りの空きセルへ結び、最後の一歩は線分検査を免除する形に直した。
2. **クリアランス 0.45 → 0.6**: 初版の経路では角がカード前面から 0.36 m しか離れず、カプセルが引っかかって最終脚だけ落ちた（12/13）。余裕を広げて解消。
