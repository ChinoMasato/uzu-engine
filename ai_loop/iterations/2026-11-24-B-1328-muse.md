## 欠陥1: 表の右端が詳細パネルの下に潜る（racing）

実測（プローブで全セルの最小幅と配置を測定）:

- **stable**: spec の表は x=17・幅743（17..760）、詳細パネルは
  x=778。だが内容の最小幅合計が列幅合計を上回り、表は実効
  768幅（17..785）に広がってパネル領域へ侵食していた。最終列
  （厩舎）の字形は x≈777 まで到達し、パネル枠（778〜）に接して
  いた。内容最小値の内訳（本文19px）: 馬名171（9字）・調子89・
  ダート／成長型はヘッダ57など、列幅合計＋separation 40＋
  両端マージン16 = **810 > 743** で、uzu_ui.h の幅の規則
  （列幅合計＋separation＋両端マージン ≤ 表幅）に違反。
- **entries**: 表は 743 のまま収まっていたが、宣言幅が内容
  最小値を下回る列が2つあった（負担重量 60 < ヘッダ実測76、
  馬番 37 < ヘッダ実測38）。馬名列が expand で残りを吸収する
  ため見た目は破綻していなかったが、規則違反は同じ。

直し方（データの中身は不変）:

- **stable**: spec の theme に `font_size: 16` を入れ（画面全体の
  書体が1段小さくなる。チップ・詳細パネルも同じテーマなので
  整合する）、列幅を内容実測に合わせて再配分した
  [44, 150, 34, 34, 87, 87, 82, 26, 50, 52, 36]。合計682＋40＋16
  = **738 ≤ 743**。再プローブで全セルの内容最小値 ≤ 割当幅、
  表の実効幅は宣言どおり 743 に戻り、字形の右端は 759
  （パネルまで約18px の間隔）を確認。
- **entries**: 馬番 37→38、負担重量 60→76。宣言幅が全列で
  内容最小値以上になった（固定列合計＋expand最小＋28＋16 =
  517 ≤ 743）。内容が元々その幅を強制していたため、描画
  レイアウトは不変で、spec が規則どおりになった。

- 副産物の知見: spec の DataTable ノードへの `"font_size"` 指定は
  キット製部品には効かない（ui_tool のテーマ上書きがキット部品
  では .tscn にシリアライズされず、セル最小幅も変わらない）。
  効くのは spec の `theme.font_size` の方。今回は theme 側で調整
  した（ノード側の指定は spec から除去済み）。

## 欠陥2: sim メインの焼き込み残片とラベルの切れ

実測（リファレンス座標で特定）: 焼き込みラベルのうち3つと
参照側タスクパネルの断片が、クロップと自前パネルの重なりで
破綻していた —— 採石場ピルはクロップ左端で切断、研究所ピルは
カレンダーパネル（x≥876）に半分隠れ、倉庫ピルは左半分が自前
タスクパネルの裏で「Lv.4」だけが断片として露出、タスクパネルの
数値列が画面左端（x 0..12）に数字の残片として覗いていた。

直し方（prep_assets.py の make_sim_map、クロップ前の参照画像
空間で消去）:

- 4箇所を近傍テクスチャのクローンで塗り替えた（採石場→岩肌、
  研究所→ファサード、倉庫→屋根瓦、タスク断片→畑）。消去
  マスクは箱の内側で完全不透明・外側の帯でフェザー（初回は
  マスクの内側フェザーがピルの金枠と字形の上端を残したため、
  マスク構造を作り替えた）。
- 代わりに spec（sim_main.json）へ自前ラベルを3つ追加した
  （既存 Fac ラベルと同書式）: 採石場 Lv.4 [16,94]／
  研究所 Lv.3 [730,140]（カレンダー左に収まる）／
  倉庫 Lv.4 [312,460]（タスクパネルの右）。いずれも画面内・
  パネル非重複を再撮影で確認。
- 丸ごと開地に収まる焼き込みラベル（製鉄所／製材所／港／
  住宅街）は B-1326 の割り切りどおり地図ラベルとして残した。

作業中の落とし穴: `uzu.py` の引数順は `engine <project> <command>`。
`engine import <project>` と書くと import は実行されず（エラーは
JSON で返る）、古い .ctex のまま撮影して一度「直っていない」と
誤認した。art 差し替え後は import の成否 JSON を必ず確認すること。
