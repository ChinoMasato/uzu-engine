# B-1317 UIモーション（2026-11-22、Muse subagent、branch agent/b-1317-muse）

## 現状確認（リードの見立てを実物で補正）

土台は想定より厚かった。UZUUIJuice（B-1304）に曲線5種（anticipation／overshoot／ease_in／bounce／step、純粋関数 `motion_value`）、再生基盤（entries＋`apply_animations(dt)`）、open／close／hover／count_up／transition、`apply_world_motion`（世界の uzu_motion から曲線・時間・steps を引く）、イベントログが既にあった。UZUUI 側にも `get_world_motion` と枠シェーダーの装飾アニメ（B-1307）があった。

足りなかったのは次の6点で、ここを実装した:

1. タスク指定の5プリセット名（appear／disappear／hover／press／value_change）での統一口がない。
2. press（押下で縮んで戻る）がない。
3. appear／disappear にフェード（modulate.a）がなく、open／close はスケールのみ。
4. value_change が整数カウント（count_up）のみで、ゲージ（Range）の現在値からの小数補間がない。
5. ai_loop/ui_tool.gd にモーション指定キーがない。
6. 時刻指定の読み戻し口（seek／state）がなく、機械検証ができない。

## 実装

### UZUUIJuice（scene/gui/uzu_ui_juice.{h,cpp}）

- 新しい Kind: UI_APPEAR／UI_DISAPPEAR／UI_PRESS／UI_VALUE。Entry に `motion`（プリセット名。従来 kind はイベント名を入れるのでイベントログ互換）と `value_from`／`value_to` を追加。
- `play_motion(control, name, options)` が統一口。options: `world`（世界の曲線・duration・steps を引く）、`curve`／`duration`／`strength`／`steps` の個別上書き、`from`／`to`（value_change の端点）。未知の motion／world／curve は false、値を保持しないコントロールへの value_change も false。
- 世界マッピングは既存規則を `_world_curve()` に切り出して `apply_world_motion` と共有: steps>0 → 曲線 "step"＋steps、overshoot>0.01 → "overshoot"（strength＝overshoot/1.70158）、他は "ease_in"。duration は世界の値、value_change のみ ×2。
- プリセットの効き方:
  - appear: scale を曲線値（最小 0.02）＋ alpha を曲線値でクランプ。開始時に表示化。
  - disappear: scale（1−v）＋ fade out、終了時に非表示化してから復元。
  - hover: scale の膨らみ（従来どおり）＋ modulate の明るさ（1＋0.10×strength×sin πt）。steps 世界では量子化 t を使うよう統一。
  - press: 1 − 0.12×strength×sin(πt) のディップ（中間で最も縮む）。
  - value_change: Range は現在値→目標値の小数補間（Range 自身が min/max でクランプ）、Label は整数。終了時は目標値に正確に着地（`_restore` の finish）。
- 機械検証の口: `get_animation_state(control)` → {animating, motion, curve, elapsed, duration, progress（量子化後の t）, value（曲線値）}。`seek_animation(control, seconds)` は elapsed を直接設定して即適用し、終端では復元＋end ログまで行う。実時間待ちなしで t=0／中間／終端を固定できる。`get_motion_names()` で5名を返す。
- `apply_world_motion` は従来 kind（open／close）のまま残した（既存テストがイベントログの "open" 件数を数えるため）。play_motion は追加レイヤー。

### UZUUIWorld の meta 再生（scene/gui/uzu_ui.cpp）

- `decorate()` が、meta "uzu_motion" を持つコントロールに `play_motion` を実行する（options の "world" 既定は自ノードの world）。stats に "motions" 件数を追加。meta のあるコントロールは既定の open をスキップする。
- **バグ修正（今回の検証で発見）**: 当初 `Dictionary options = spec;` と書いたところ、C++ の Dictionary は参照型のため `options.erase("preset")` が元の spec＝保存済み meta 自体から "preset" を消してしまい、play_motion に空名が渡って常に false になっていた。`spec.duplicate()` に修正。GDScript 側の複製コードでは duplicate を使っていたため再現せず、C++ テストでのみ落ちた。

### JSON 指定（ai_loop/ui_tool.gd）

- 共通キー "motion" を追加。値はプリセット名の文字列、または {"preset", "duration"(0.01〜10), "strength"(0〜3), "from", "to"} のオブジェクト。名前は UZUUIJuice.get_motion_names() と突合して検証し、ノードに `set_meta("uzu_motion", {...})`、件数を counts["Motion"] に加算。既存仕様は互換維持。
- 実機検証（この worktree の editor バイナリ）: 正常系（文字列形式1＋dict 形式2、world persona）→ UI_RESULT ok=true、Motion=3、保存された .tscn に `metadata/uzu_motion` が3ノード分入ることを確認。異常系（未知プリセット "explode"、duration 99）→ ok=false、problems が「needs one of appear, disappear, hover, press, value_change」「needs a number of seconds between 0.01 and 10」と箇所付きで返ることを確認。

## テスト

新規10件（tests/scene/test_uzu_ui_juice.cpp に9件、test_uzu_ui.cpp に1件）:

- プリセット名5種の固定。
- persona appear: t=0 で scale 0.02・alpha 0、seek(0.7×duration) で scale>1 のオーバーシュート、終端で完全復元。state で duration 0.18・curve "overshoot" を確認。
- pixel appear: steps で scale が 0.25 に保持される（カクカクの固定）。
- wafu disappear: 中間で 0<alpha<1、終端で非表示＋復元。
- press: 中間 scale＝base×0.88、終端復元。
- play_motion 経由 hover: scale 1.1＋modulate.r>1、終端復元。
- wafu value_change: 現在値 20→80、単調増加、t=0.5 で 72.5、duration は世界の2倍（0.7）、終端で正確に 80。
- persona value_change: t=0.7 で 100 超えのオーバーシュート、終端で正確に 100。
- 拒否系: 未知 motion／world／curve、値を持たない Panel への value_change、idle への seek は false。
- UZUUIWorld: meta のモーションが decorate で再生される（stats["motions"]==1、state の motion=="appear"）。

全スイート結果（この worktree・このマシン）: **1594 件中 1592 pass、fail は既知の [UDPServer] 2件のみ**（アサーション 627,956 件中 29 fail で、ベースライン計測と一致）。ベースライン 1584 件からの差分 +10 が新規分。

### テスト環境の注意（切り分け済み）

開発中、拒否系テストが「[SceneTree] タグなし＋他ケースの後」でのみ SIGSEGV する現象を追った。切り分けの結果: cancel_all・memnew(Node)・memnew(Control) は無事で、タグなし環境で Panel を生成する箇所で落ちる（エンジン側バックトレースはシンボル剥離のため関数名まで特定できず）。同ファイルの control 生成ケースは従来から全て [SceneTree] 付きであり、本ケースも [SceneTree] を付けて解消した（全スイート完走で確認）。エンジン本体のバグと断定できる材料はないので、切り分け結果のみここに残す。

## 見本（ai_loop/look_samples/b1317/）

persona と wafu の2世界観 × 出現直後／中間／完了の6枚（`<world>_<phase>.png`）。プロジェクトは `project/`（フォントは B-1316 規約どおり hikari のチェック済み JP フォント game_font.ttf をテーマに明示）。画面はパネル appear＋ボタン press＋ゲージ value_change（10→90）を並べ、main.gd が毎フレーム deferred で seek して位相を固定する（実行時ドライバが同フレーム内で進めるため、deferred で最後に効かせるのが要点）。

目視確認:
- persona: start でパネル不可視（scale 0.02・alpha 0）、mid でパネルが終端より大きく膨らみ（オーバーシュート）、ゲージのセグメントがパネル右端を突き抜ける（値のオーバーシュート）、ボタンは press の窪み。end で全て正確な終端。
- wafu: start でパネルが小さく幽かに、mid で半透明のまま成長しゲージ約72%、ボタン縮小。end で完全な姿＋ゲージ90。世界差（速さ・オーバーシュート有無・ease の質）が静止画でも読める。

観察（B-1317 の範囲外、B-1315 へ）: persona のパネル背景は中央に黒い楔状の抜けがある（全位相で同一＝モーション起因ではない。persona テーマの枠テクスチャ側の見え方）。wafu のキャプション文字が暗背景で読みにくい（見本側のラベル色）。
