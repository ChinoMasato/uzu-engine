# B-1228 カード分割の物体単位化の検討 — 2026-11-28（リード）

## 判定：採用方向（試作成功）。本実装は後続項目 B-1230 へ

moonpost の仕様イラストから、レジストリの bbox を種にした古典手法で家3軒を個別カードとして切り出せた。ML セグメンテーションは不要だった。

## 試した2方式と数値

対象は elements.json の家3軒の bbox（作業解像度 768×432、bbox を 18% 拡張して切り抜き）。指標は bbox 内の前景率 fg_ratio と、bbox 境界に前景が触れる割合 border_touch。

- **v1：境界色の中央値への距離＋氾濫**（`object_cut_prototype.py`）— 失敗。fg_ratio は tol=18 で 0.97〜1.0。切り抜き範囲の境界は空・通り・木々が混ざり、単一の中央値色がどれも代表しない。コンタクトシートでも空の一部しか抜けなかった。
- **v2：境界シードの領域成長（局所平滑のみ通過）**（`object_cut_prototype_v2.py`）— 成功。1ステップの色差が閾値以下の画素だけを背景として広げる。絵の輪郭線（強いエッジ）が成長を止める。
  - step_tol=10：fg_ratio は red 0.794／tower 0.684／green 0.574、border_touch は 0.508／0.456／0.335。
  - 目視（`samples/moonpost/object_cut/contact_sheet.png`、マゼンタ合成）：3軒とも家として完結した切り抜き。塔の家はほぼ清書レベル。残る欠陥は3点に集約される：(1) 家の手前の地面・通りが接地面で 붙いて残る（地面は Ground カード側の領分なので、本実装では bbox 下端の接地帯を切り離す規則が要る）、(2) 範囲端に写り込む隣接物（郵便屋）の部分混入、(3) 柔らかい境界のフリンジ。
  - step_tol=6 では背景の取り残しが増え（fg_ratio 0.74〜0.83）、14 では屋根や壁へ食い込む（fg_ratio 0.40〜0.55）。10 がこの絵では適正。

## 併用形の結論

- 帯状カード（現行）は背景・地面・遠景の土台として維持し、物体カードはレジストリ要素（basis=observed/inferred の bbox がある要素）に対してだけ v2 方式で追加生成する二層構造が自然。物体カードが取れた要素は Backdrop への対応づけから外せる。
- 本実装の条件：ai_loop は標準ライブラリ＋PIL 任意の流儀なので、領域成長は純 Python（deque）で image_scene.py に入れる。作業解像度 768 幅なら実用速度になる見込み（本試作は numpy 版で切り抜き1件あたり約1秒）。
- 接地帯の分離と隣接物の混入対策（成分の bbox 内占有率で足切り）は B-1230 で扱う。
