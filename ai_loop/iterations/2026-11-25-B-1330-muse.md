# B-1330 『スターホース牧場』U.ZU 版の最高品質化（2026-11-25、担当 muse）

千野の指示「クオリティが低すぎる。U.ZUエンジンの素材をすべて活かした、
今作れる最高品質のゲームにしてください」を受け、B-1329 のミニ版
（牧場／出馬表＋矩形と円のレース）を、支給アート（ChatGPT 生成、
~/workspace/starhorse-art/）を使ったアート主導の構成に作り替えた。
エンジン／キット側のコードは無変更（差分は ai_loop/samples/starhorse/
と CLAIMS のみ）。

## 作ったもの

- **タイトル画面（新設）**: title_keyvisual 全面＋ロゴ「スターホース
  牧場」92px（白・縁取り #201405 16px・金の影）＋タグライン＋
  メニュー2ボタン。出現モーション（appear＋sweep）と背景パララックス、
  塵モート。BGM は B-1329 のものを継続し、ここから再生。
- **牧場／出馬表**: farm_bg 全面アートの上に B-1326 racing キットの
  パネルを埋め込む B-1325 の型に変更（従来の全面パネル＋タブ地を廃止）。
  データ部品と行選択→詳細パネルの連動は B-1329 を維持。画面別の
  背面 fx（塵）・フォーカス burst・押下 flash を配線。
- **レース（全面刷新）**: 横視点 2.5D。racecourse_bg を遠景
  （空＋スタンド、rows 0..500）／芝（rows 500..800）／手前ラチ
  （rows 765..941、緑優位キーで芝を透明化）の3層に分解し、
  速度比 0.25／0.55／1.3 のパララックス。馬は horse_gallop を
  B-1324 の局所テクスチャ分離（分離軸は色でなく局所 std）で
  切り抜き、HSV マスク差し替えで8頭分：馬体は毛色8種に
  グレーディング、勝負服・帽子・鞍下は枠色系に差し替え
  （prep_assets.py、勝負服の色相が 327–350° に集中すること、
  手綱の影がマスクに漏れることを実測して範囲を絞った）。
  ゼッケン番号は鞍位置のチップ、馬名は頭上のタグ（団子状態でも
  読めるよう枠番で2段にずらす）。ギャロップ周期の上下動＋体の
  傾き、速度に応じた残像（2枚）とスピード線、土煙パーティクル
  （自前配列、上限240）。カメラは集団の先頭が画面60%に来るよう
  追従し、残り400mから 8.6→11.0 px/m へ寄る。ゴール前は
  スローモーション（×0.32、勝ち馬のゴールで解除）＋フラッシュ／
  シェイク（控えめ）。200m毎の距離マーカーとゴールポスト。
  シム（脚質・疲労・順位）と実況同期（commentary.gd）は B-1329
  資産を再利用、字幕表示は維持。ライブ順位パネルは半透明の濃緑
  地に残り距離と馬身差を併記。
- **結果画面（追加、result.gd）**: 競馬場アート全面＋着順表
  （キットの DataTable、タイム／着差つき）＋勝ち馬の疾走カット
  600×304＋ファンファーレ（BGM バスで再生）。
- **画面遷移**は全て UZUUIJuice.transition（0.28s）＋slash に統一。

## 検証

- 自動プレイ（verify_race.py、固定シード1329・30倍速）: **pass**。
  8頭全馬完走、勝ち馬ハヤテノツバサ 103.58秒、全結果に着差文字列、
  実況19本が局面順に発火（01→02→03→05→07→08→09→10→11→12→
  13→14→17→18→20→23→27→28→29）。B-1329 との差として、馬の
  位相用に乱数を追加で引くため出遅れ判定が 04 でなく 05 になった
  （シード決定的なのは不変、検証側は両対応）。
- 撮影（shots/）: title／farm／entries／race_start／race_mid／
  race_final／result の7点＋動画 motion_race.mp4（11秒・331
  フレーム。フレーム番号の欠落で ffmpeg が途中で止まった短縮版）。
  目視確認済み：タイトルのロゴとアート、牧場／出馬表のアート＋
  パネル埋め込み、レースの馬群（毛色・勝負服の見分け、チップ、
  2段タグ、字幕、順位パネル）、結果の着順表と勝ち馬カット。
  ※ 2026-11-25 のオーナー指示で撮影・動画まわりの作業は打ち切り
  （最終確認は書き出し exe でオーナーが直接行う）。動画の
  エンコード欠落対策（連番振り直し）は capture_video.py に
  入れたが、再生成はしていない。遠景の継ぎ目は当初クロスフェード
  のゴーストが目立ったため、鏡面タイリング（交互反転）に変更し
  解消を確認した（この変更後のレース静止画はデバッグ撮影で確認、
  shots/ の race_* は変更前のもの）。
- レース中 fps: lavapipe（ソフトウェア Vulkan、1152×648）で
  平均 **3.4**（shots/stats.json）。ただし計測中はエンジン本体の
  ビルドが同じ 1.5 コアを奪っており、B-1329 の 31.8（競合なし）
  と単純比較できない。実 GPU での値は未計測。
- 品質ゲート／包含: キット側コードが無変更のため B-1328 時点の
  pass（ゲート全6項目・包含 全38画面）がそのまま成り立つ。
  差分範囲は git status で確認済み。
- 全テスト: 本ブランチのバイナリで **1604/1606 pass**。失敗は
  既知の環境起因 [UDPServer] 2件のみ（tests/core/io/
  test_udp_server.cpp、サンドボックスの UDP 由来で無変更
  バイナリでも再現するもの）。

## 作業中に直した不具合（いずれも本実装側）

1. 新規 result.gd の class_name がクラスキャッシュ未登録で
   main.gd がパースエラー → 再インポートで解消（あわせて、
   スクリプトが読めないとメインシーンが無言で止まるため、
   検証は必ずログの SCRIPT ERROR を見ること）。
2. `draw_stylebox` は `draw_style_box` の誤記（パースエラー）。
3. 馬の描画：`draw_texture` は原寸描画なので、変形行列に
   表示サイズへの縮率を持たせた（当初は原寸 1150×582 で
   描かれ、体が画面外にはみ出していた）。
4. 結果画面の勝ち馬カット：TextureRect の expand_mode 既定が
   サイズ指定を上書きし原寸表示になっていた →
   EXPAND_IGNORE_SIZE を明示。
5. 撮影ハーネス：結果画面待ちが実況の実時間ドレインで終わらず、
   撮影ドライバ側でも実況を高速モードにした。あわせてレース
   撮影を 12 倍速化しタイムアウトを 2400 秒に。タイムアウトで
   殺した撮影の godot 子プロセスが残留して CPU を奪い続ける
   事象があり、明示 PID で終了させた（pkill -f は自分のシェルを
   巻き込むので使わない）。

## B-1329 との差（比較所見の更新）

- 画面の情報量が根本的に変わった：全面アート＋実馬スプライトで、
  B-1329 の「矩形＋円」とは別物になった。UI 構築の手間は
  B-1329 と同程度（spec の差し替えと art レイヤー追加が中心）で、
  品質差はほぼ素材とレース描画層から来ている——「エンジンの
  素材を活かす」指示への答えとして、キット部品（DataTable／
  DetailPanel／Chip／Juice／fx）はそのまま品質の土台になった。
- 実況・シム・検証の資産は無改変で再利用でき、verify は
  表現層を総入れ替えしても同じ物差しで pass を示せた。

## 残った限界（正直に）

- 馬は単一ポーズの静止画で、脚の動きは上下動と傾きのみ。
  本物のギャロップアニメーション（複数フレーム）には
  フレーム素材が要る。
- 遠景の継ぎ目：クロスフェード帯で建物のゴーストが薄く残る。
  撮影で拡大すると分かる水準。
- var0（1枠）の勝負服の端に僅かなピンク残りがある
  （レース表示サイズでは判別できない水準）。
- レーンの前後差は 6px 刻みで、序盤の団子状態では馬同士が
  大きく重なる。横視点の宿命ではあるが、レーン差を広げると
  今度はコース幅の嘘が増える。
- lavapipe の fps はビルド競合下の参考値。実 GPU（千野の
  RTX 4050 等）での見え方・速度は未確認。
- 撮影ハーネス（capture.py）は lavapipe のフレーム単価に
  強く依存し、環境が重いと結果画面まで届かないことがある。
  結果画面は同一コードのデバッグ撮影で得た。オーナー指示で
  撮影系は打ち切りのため、capture.py の完走再確認は行わない。
- Windows exe のテンプレート：既存の windows_release_x86_64.exe
  は 2026-11-20 ビルドで、B-1312 以降の UZUUI 追加分
  （make_data_table 等）が入っていないことを strings で確認した。
  そのまま使うと牧場画面でメソッド不在のエラーになるため、
  本ブランチのソースから Windows テンプレートを作り直して
  差し替えた（旧ファイルは .bak-20261125 として保存）。
  新テンプレートに make_data_table／make_stat_bar／
  draw_backdrop／UZUTouchStick／get_type_scale が含まれることを
  strings で確認済み。MinGW は posix スレッド版に切替えて
  ビルド（1時間31分）。
- 書き出し結果：export_presets.cfg（Windows プリセット）を追加し、
  本ブランチのエディタで --export-release を実行、rc=0・
  SCRIPT ERROR なし。starhorse.exe（PE32+ x86-64 GUI、
  81,261,568 バイト）＋ starhorse.pck（36,141,812 バイト）。pck 内に main.tscn／全画面シーン／art／スクリプト／
  音声／フォントが含まれることを strings で確認した。
  zip は ~/workspace/your_files/starhorse-uzu-win.zip
  （56,527,872 バイト）。Windows 実機での起動確認はオーナーが
  この exe で直接行う（この VM では Windows バイナリを実行
  できないため、書き出し版そのものの起動は未検証。同一
  プロジェクトがエディタバイナリで起動・完走することは
  検証済み）。
