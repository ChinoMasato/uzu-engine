## (A) 質感

### グラデーション（UZUUI のスタイルキー追加、C++）

- frame 系: `gradient_to`（第2色）＋ `gradient_dir`（down 既定／up／left／
  right）。素材描画の前に地色を軸方向に線形補間してから素材を重ねる。
  グラデーションの走る軸は StyleBox の STRETCH に固定する（帯の形状を
  保つ skew の縦軸と同じ理由: タイル繰り返しや TILE_FIT のリスケールは
  グラデーションの端をパネル端に固定できない）。ただし halftone 枠の
  横軸は TILE のまま（ドット格子をリスケールするとモアレになるため、
  halftone 枠のグラデーションは縦方向のみ）。
- backdrop 系: 地に `gradient_to`／`gradient_dir`（diag 追加）、斜帯に
  `band_gradient_to`（帯幅方向＝帯の法線方向に流れる。帯は回転した矩形
  なので、流れは帯のローカル座標で付ける）。
- persona プリセットへの適用（ベタが正しい所は不変）:
  - frame: 地 #e60012 → `gradient_to #c40010`（down）。光が上から落ちる
    程度の弱い流れ。
  - backdrop: 地 #0a0205 → `gradient_to #180409`（down）、帯は
    `band_gradient_to #a80010`（帯の上縁が明るく下縁が沈む）。
  - ボタン（フォーカス反転バー含む）は従来どおりベタ。反転の読みは
    純色の面で担保する。

### ハーフトーン改修

- ピッチ: スタイルキー `halftone_cells`（タイル256pxあたりのセル数、
  既定32＝8px）でパラメータ化。persona は **64＝4px** に細密化。
- ドット色: スタイルキー `halftone_dot`。persona は **#7d000d**（地の
  シグナルレッドの陰色＝濃いマルーン）。未指定時は従来どおり
  地色の darkened(0.3)（純黒にはしない）。
- 縁: ドット被覆率を距離に対する約1.1px の滑らかな落ちに変更（AA 円）。
  旧版は半径で硬く段になっていた。
- backdrop の斜帯ハーフトーンにも同じ HalftoneSpec を配線（帯と枠で
  ピッチ／インクが揃う）。

### ピッチを指示の例示（5〜6px）でなく 4px にした理由

ゲートの設計パターン判定は「自己相関が整数周期で折り返せること」が
前提で、非整数周期はリスケーリングのモアレの署名として Python テスト
（test_moire_grid_fails_on_residue、8.5px ドットは fail）が守っている。
5〜6px はセル数換算で 42〜51 セル＝タイルも中帯（skew 128px）も割り
切れず、継ぎ目で位相が跳ぶ。よってゲート側は変更せず、整数周期で
最も細かい 4px（64セル）に合わせた。実測: シート周期 [4,4]・残差
0.033（旧 [8,15]・0.26 より大幅に清浄）。

### シートフィクスチャの是正（副産物）

新ピッチで当初 texture_sheet が fail（残差 0.78）。切り分けの結果、
テクスチャ自体は完全な 4px 格子で、失敗は見本シート側だった:
sheet パネル（1024×512）が skew 枠の縦 STRETCH（B-1319 の規則）で
テクスチャを約1.875倍に引き伸ばし、8px→15px の旧測定は「整数に
落ちた偶然」で通っていた（4px→7.5px は半整数になり折り返せない）。
texture_repetition_sheet の文書化された方法は「原寸で測る」なので、
`_sheet()` を stylebox からテクスチャ原寸の高さを導いてパネル高に
する构造に変更し、ゲートの窓を (320,120,512,200) に移した（従来
320,196,512,256）。ゲートの判定ロジック自体は無変更。

## (B) 3D UI 試行（ai_loop/look_samples/b1321/）

独立プロジェクト（Forward+、1152×648）。全構築をコード（main.gd）で実施:

- 地: UZUUI.draw_backdrop（帯・星なし）をテクスチャ化した QuadMesh。
  斜帯2本は実体の Box（白線・黒下敷き付き）で交差させる。
- ロゴ: Label3D 白（黒縁）＋赤コピーのオフセットで 2D の版ずれを再現。
  バー: 平行四辺形プリズム（SurfaceTool、面ごとに明示法線）の白縁＋面
  ＋Label3D。スパークルはビルボード Quad、赤リングは TorusMesh、
  透かしは Label3D。
- メニュー版（UZU_B1321_SCREEN=menu）: 厚みのある傾いたパネル＋
  PAUSE 透かし＋HP/MP ゲージ＋小バー4本。
- 質感: PBR（粗さ違いの赤／黒／白）、DirectionalLight＋環境、ACES
  トーンマップ。フォーカスバーの赤は光の当たり角で沈むため emission
  0.45 を足して 2D の反転の強さに寄せた。パネル面も emission 0.22。
- モーション: 出現はスタッガ 0.07s の斬り込み（奥／横から＋回転収束、
  ease_out_back）、フォーカス巡回（3.2s／4.6s で切替＋パルス）、
  カメラリグのサイン揺れでパララックス。UZUUIJuice の考え方を 3D
  トランスフォームで再現した範囲。
- 成果物: title3d.png／menu3d.png（静止画、UZU_B1321_STILL=1）、
  motion_title3d.mp4（13秒・30fps）。

### 所感（2D 版との比較）

- 絵面の差: 帯とバーの「厚み」と光の当たりは実物感があり、特に斜帯の
  交差部とリングは 2D の平坦な印刷感より情報量が多い。一方で persona
  の肝であるハーフトーンの印刷感は 3D 側では再現していない（パネルは
  ベタ＋emission）。2D の「印刷物の鋭さ」と 3D の「実物の重さ」は
  別方向の質感で、タイトル画面の第一印象は 3D が濃いが、文字の
  キレ・情報の読みやすさは 2D が上（Label3D は縁の AA が弱く、
  小さい文字が滲む）。
- コスト: 構築は main.gd 約450行（部品化なしの直書き）。2D 側の
  spec→tscn 生成と違い、レイアウト調整が座標の手計算で、パネルの
  斜行に内容を収める計算（左端が行ごとにずれる）も手作業になった。
  包含ゲートのような機械チェックは 3D 側にまだ無い。
- 実用化への課題: (1) Label3D の小文字の滲み（pixel_size とフォント
  サイズの兼ね合い、MSDF 化が要る）、(2) ハーフトーン等の印刷素材を
  UV 付きメッシュ＋テクスチャで持ち込む経路、(3) レイアウトを
  spec 化しないと画面追加が高コスト、(4) フォーカス等の状態管理は
  2D の Theme/StyleBox のような受け皿が 3D 側に無い。タイトル画面の
  ような「見せ場」1枚には有効、本編 UI の置換は時期尚早という印象。
