# B-1702 Godot 再生ヘルパーの標準化（UZUGameAudio）— Gemini 4 (AI Studio) 実装・リード統合 (2026-11-28)

担当: Gemini 4 Hydrogen（AI Studio ブラウザ経由、指示書＋土台コード全文をアップロードして生成→リードが適用・検証）。AI Studio 経路の3例目。

## 成果物
- `ai_loop/uzu_game_audio.gd`（新規）: Lumina SFX 同梱 `game_audio_helper.gd`（コードは MIT、出典表記と適合内容をヘッダーに保持）を取り込み、U.ZU 標準の再生面に適合。
  - クラス名を `UZUGameAudio` に変更（本家ヘルパーとの衝突回避）。
  - プールのテイク数は「ちょうど3」から「1以上」に緩和（B-1701 の橋は通常1ファイルを配置するため）。
  - イベント名の統一口を追加: `register_event`（ファイル）／`register_synth_event`（B-1105 UZUSfx プリセット、初回再生時に生成してキャッシュ）／`play_event`（file／synth 共通、位置・減衰・ピッチゆらぎつき）／`start_event_loop`（file 専用）／`describe_events`（AI 向けの登録一覧）。
  - 元のプール／ループ／天候・RPM 連動／距離減衰の API は意味を変えず保持。
- 自己検証プロジェクト `ai_loop/samples/game_audio_check/`（project.godot／main.tscn／check.gd）: プール巡回・位置・減衰伝播・ピッチ（jitter 範囲と jitter 0 の正確値）・ループの開始／天候の単調増加／RPM のピッチ変化／停止・file イベント（実 WAV 読込）・synth イベント（UZUSfx 生成）・describe_events を検証し `UZU_AUDIO_CHECK {json}` を出す。
- テスト `ai_loop/tests/test_game_audio.py`: 静的契約（クラス名・出典表記・必須関数）＋バイナリがある環境での実行検証（無い環境では skip）。
